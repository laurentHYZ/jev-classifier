#+title: Jev Classifier
#+subtitle: type-safe text classification in the browser, via OpenRouter's Decisions API

A static page. Paste text, define typed questions (=choice=, =score=, =noul=),
get structured answers with probabilities and confidence. No build step, no
dependencies, no server.

* Live demo
[[https://laurentHYZ.github.io/jev-classifier/][laurentHYZ.github.io/jev-classifier]] — paste your own OpenRouter key and go.

* Bring your own key
Both pages ask for an OpenRouter API key (=sk-or-…=) and send it directly to
=openrouter.ai= as =Authorization: Bearer=. It is never stored and never passes
through any server of this project — there is no server.
Get a key at [[https://openrouter.ai/keys][openrouter.ai/keys]]; Jev is billed per input token (~$0.04 / 1M).

* Why it works from a static page
OpenRouter's Decisions API answers preflight requests with
=access-control-allow-origin: *=, so a browser can call it cross-origin with the
visitor's own key. (TypeSafe's own =api.typesafe.ai= sends no CORS header and
would need a proxy.)

* The request
#+begin_src json
POST https://openrouter.ai/api/alpha/decisions
Authorization: Bearer sk-or-...

{ "model": "typesafe/jev-1.13",
  "state": "<text to classify>",
  "questions": { "<id>": { "type": "choice" | "score" | "noul", ... } } }
#+end_src
Each answer carries a =type= and is nested under =answers= in the response.
Check =type= before reading =choice=, =score=, or =noul= — the last is the 0–1
probability. A =type= of ="refusal"= means that question was not answered; treat
it as "not answered", never as a negative.

* Layout
| file         | role                                                          |
|--------------+---------------------------------------------------------------|
| =index.html=   | UI: state editor, question builder, result rendering           |
| =demo.html=    | focused single-file demo: ticket triage in ~180 lines          |

=index.html= is the GitHub Pages landing page. =demo.html= is the "start here"
example: a textarea, one button, and three questions (=kind= choice,
=needs_reply= noul, =urgency= score) with result bars. Either file runs by
opening it from disk.

* Primitives used
- =choice= → one label from a closed set, with =probabilities= and =confidence=
- =score=  → position on an ordered rubric (probabilities + =legend= of levels)
- =noul=   → probability that one statement is true (0–1)

Questions are atomic and independent; combine them in code (or in the UI) rather
than asking one vague question that weighs several factors.

* Notes
- Never log or commit a key; the key field is =type="password"= and is not stored.
- Other decision models (Cloudflare Clef, Liquid D1, Mercury Decide) speak the
  same API — only =model= changes.
